## 2. Frontend Architecture

### 2.1 Routing (React Router Data Mode)

All routes defined in `/routes.ts` using `createBrowserRouter`. The root layout is `AppShell` which provides the sidebar, top bar, and language switcher. Authentication is enforced via `AuthGuard`.

```
/login          -> LoginPage
/dashboard      -> DashboardRouter (role-based redirect)
/crm/*          -> GuardedCRM (34 CRM sub-pages)
/hr/*           -> HR pages (8 sub-pages)
/admin/*        -> Admin config pages
/student/*      -> Student portal pages
/teacher/*      -> Teacher portal pages
/system/*       -> System management pages
/config/*       -> Institute configuration
/mentor/*       -> Mentor portal
/marketing/*    -> Marketing dashboard
/messaging      -> MessageCenter
/reports        -> ReportsOverview
```

```typescript

export function getAll(): T[] { return data; }
export function seed(): void { /* idempotent demo data */ }
```

### 2.3 Validation Layer (Zod)

All data parsing uses Zod schemas from `src/lib/schemas.ts` (77 schemas).

```typescript
// Safe parsing with fallback
import { zodParse, zodValidate } from '../lib/error-utils';
import { LeadSchema } from '../lib/schemas';

const lead = zodParse(LeadSchema, rawJson, fallbackValue);
const { success, data, error } = zodValidate(LeadSchema, input);
```

Zero `as any` casts in the codebase. The deprecated `safeJsonParse<T>` has been fully migrated to `zodParse`.

### 2.4 Internationalization (i18n)

Three-language support with the `useLanguage()` hook from `LanguageContext`:

```typescript
const { language, setLanguage, t, isRTL } = useLanguage();

// Translation lookup
t('dashboard');  // -> "Dashboard" | "داشبورد" | "لوحة القيادة"

// Inline pick for component-level strings
import { pick } from '../lib/useTranslation';
const label = pick(language, 'English', 'فارسی', 'العربية');
```

**CSS Rules**:
- Use logical properties only: `ms-4` (margin-inline-start), `me-2` (margin-inline-end), `text-start`, `text-end`
- Never use `ml-`, `mr-`, `left`, `right` (they break in RTL)
- The `dir` attribute is set on `<html>` based on `isRTL`

Translation files: `src/translations/en.ts`, `fa.ts`, `ar.ts`.

### 2.5 Calendar

Jalali (Solar Hijri) calendar used throughout:
- `src/lib/calendar-utils.ts` — conversion utilities (Jalali <-> Gregorian)
- `src/utils/persianCalendar.ts` — Persian date formatting
- `src/lib/jalali-cron.ts` — Cron scheduling in Jalali dates
- `src/components/common/PersianDatePicker.tsx` — Date picker component

## 3. Backend Architecture

### 3.1 Dev Server (`/server/`)

Express.js server for local development with in-memory fallback:
- Port 5000 (configurable via `PORT` env)
- 25+ route modules under `server/routes/`
- Socket.IO for real-time notifications and CallerN signaling
- JWT authentication via `server/middleware/auth.ts`
- AI services via `server/services/ollama.ts` (Ollama-first, OpenAI fallback)

### 3.2 Production Server (`/backend/`)

Production-grade Express server:
- Drizzle ORM with 20+ PostgreSQL tables (`backend/src/db/schema/`)
- Rate limiting, Helmet security headers, CORS
- Structured logging via Winston
- Kavenegar SMS service
- Shetab/Shaparak payment gateway

### 3.3 Database Schema (Drizzle ORM)

Key tables: `users`, `courses`, `quizzes`, `assignments`, `attendance`, `wallet`, `gamification`, `crm`, `callern`, `messages`, `notifications`, `documents`, `marketing`, `hr`, `payroll`, `programs`, `projects`, `security`, `placement`, `student_progress`, `ai_scoring`, `assessment`, `linguaquest`, `cms`.

### 3.4 AI Provider Fallback

```
Request -> Ollama (localhost:11434) -> Success? Return.
                                    -> Fail? -> OpenAI API -> Return.
                                              -> Fail? -> Graceful error.
```

Services: essay scoring, speaking evaluation, grammar checking, flashcard generation, homework generation, dropout prediction, attendance anomaly detection, skill radar analysis, content generation, session summaries, lesson generation.

## 4. Security Model

### 4.1 Two-Layer Access Control

**Layer 1 — Route-level Role Gates** (defined in `GuardedCRM.tsx` and `AuthGuard`):
```typescript
const CRM_ROLES = ['admin', 'call_center', 'supervisor', 'front_desk', 'marketing', 'mentor', 'teacher', 'accountant'];
const STAFF_ROLES = ['admin', 'supervisor', 'accountant', 'front_desk', 'marketing'];
const FINANCE_ROLES = ['admin', 'supervisor', 'accountant'];
const ADMIN_ROLES = ['admin', 'supervisor'];
```

**Layer 2 — FACS (Feature Access Control System)** (`feature-permissions-store.ts`):
Granular boolean matrix of `feature_key x role`. Admins can toggle features per role at runtime.

Key security boundaries:
- Teacher: CRM access for own classes only, no financial data, no staff panels
- Student: Learning portal only, no CRM, no admin
- Call Center: CRM pipeline + VoIP, no financial reports

### 4.2 Authentication

- Session-based via `sessionStorage` (frontend)
- JWT tokens (backend API)
- OTP via Kavenegar SMS (production)
- DevRoleSwitcher for development (disabled in production)

## 5. Real-Time Communication

- **Socket.IO**: Notifications, CRM lead updates, attendance events, chat messages
- **WebRTC**: CallerN video calls (peer-to-peer with signaling server)
- **Notification Manager**: Server-side notification routing with SMS fallback
